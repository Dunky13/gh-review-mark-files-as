# Release 1.1.1 handoff

Filtered buttons could show zero matches on GitHub's redesigned pull request pages even when matching files were loaded. The extension looked for a titled diff link or path-valued aria-label. GitHub's current renderer instead uses an untitled link with a plain filename code element and aria-labelledby on the file region.

The fix reads the plain filename from the corresponding file-header wrapper and removes GitHub's surrounding U+200E display markers. It preserves classic path sources and leaves ambiguous rename descriptions untouched without an explicit path. Zero-target tooltips explain missing paths or unmatched/unloaded files and also appear on the surrounding label when the checkbox is disabled.

## Evidence and validation

Source-derived fixtures use GitHub's public DiffUnmemoized and DiffFileHeader renderers:

- https://github.githubassets.com/assets/ux-3d12fe8ed63c00d2.js
- https://github.githubassets.com/assets/jf-a46481f0216cad9e.js

New regression tests fail against 1.1.0 with Mark Tests (0) instead of Mark Tests (4), then pass with the fix on both /files and /changes. Tests cover a second Tests button using **/*.test.*, asynchronous replacement of all Viewed controls, marking/unmarking, root filenames, exclusions, unrelated code text, and ambiguous rename safety.

All 34 Node/jsdom tests, the four runtime-script syntax checks, and git diff --check pass locally. A browser fixture with 17 file controls reproduced zero targets before the fix and four targets after; clicking marked exactly those four files and clicking again unmarked them. The reported private PR was not tested in an authenticated browser session; GitHub state acknowledgement was simulated in the fixture.
